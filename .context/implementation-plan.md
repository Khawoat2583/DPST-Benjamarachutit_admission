# แผนการจัดเตรียมโครงสร้างระบบ (Project Initialization Plan)

แผนงานนี้กำหนดขั้นตอนในการเริ่มต้นสร้างโครงสร้างของระบบรับสมัครนักเรียน พสวท. โรงเรียนเบญจมราชูทิศ โดยใช้สถาปัตยกรรมที่ผู้ใช้งานเลือกใช้งาน พร้อมติดตั้งเครื่องมือรับประกันคุณภาพและความถูกต้องของระบบแบบครบครัน

---

## ส่วนที่ต้องผ่านการพิจารณาจากผู้ใช้งาน (User Review Required)

> [!IMPORTANT]
> **การใช้ Docker สำหรับฐานข้อมูล PostgreSQL ท้องถิ่น:**
> ในการพัฒนาและทดสอบระบบบนเครื่อง macOS เราจะใช้ Docker Compose ในการรันเซิร์ฟเวอร์ฐานข้อมูล PostgreSQL จำลอง เพื่อให้แน่ใจว่าการตั้งค่าและสภาพแวดล้อมตรงกับ Linux VPS ที่เป็น Production จริง โดยผู้ใช้งานต้องทำตามรายละเอียดใน [postgres-security-guide.md](.context/postgres-security-guide.md)

> [!NOTE]
> **การใช้ Tailwind CSS ร่วมกับ CSS Modules:**
> ระบบ Shadcn UI จะติดตั้ง Tailwind CSS เป็นพื้นฐานสำหรับจัดแต่งดีไซน์โครงสร้างหลัก (ปุ่ม, เมนูนำทาง, ตาราง) ในขณะที่เราจะใช้ CSS Modules ในการเขียนสไตล์ที่ซับซ้อนและมีรายละเอียดเฉพาะทาง (เช่น หน้าฟอร์มกรอกเกรดวิชาพื้นฐาน) เพื่อควบคุมความเป็นระเบียบและประสิทธิภาพสูงสุด

## ขั้นตอนการติดตั้งและสถาปัตยกรรมที่เสนอ (Proposed Steps)

### 1. การริเริ่มสร้างโปรเจกต์ Next.js (Next.js Initialization)
เริ่มจากการตรวจสอบคำสั่งการสร้างในรูปแบบ Non-interactive เพื่อติดตั้งเทมเพลตมาตรฐานโดยไม่ต้องรออินพุตจากผู้ใช้:
```bash
npx create-next-app@latest ./ --typescript --eslint --tailwind --src-dir --app --import-alias "@/*" --yes
```
*หลังจากรันคำสั่งนี้ โปรเจกต์ Next.js 15+ พร้อม TypeScript และ Tailwind จะถูกสร้างขึ้นในโฟลเดอร์หลักทันที*

ก่อนรันคำสั่งนี้ต้องตรวจสอบว่าเครื่องมือสร้างโปรเจกต์จะไม่ลบหรือเขียนทับโฟลเดอร์ `.context/` และ `data/` ที่มีเอกสารและไฟล์อ้างอิงอยู่แล้ว หากคำสั่งไม่ยอมสร้างในโฟลเดอร์ที่ไม่ว่าง ให้สร้างใน temporary directory แล้วค่อยย้ายไฟล์โปรเจกต์เข้ามาโดยไม่แตะต้องข้อมูลอ้างอิงเดิม

### 2. การกำหนดค่าระบบจัดแต่งสไตล์ (Styling Configuration)
*   **Shadcn UI:** ทำการติดตั้งและกำหนดค่าเริ่มต้นสำหรับส่วนประกอบพื้นฐาน:
    ```bash
    npx shadcn@latest init
    ```
*   **CSS Modules:** จัดเตรียมโครงสร้างไฟล์สำหรับเขียนสไตล์ที่ Component-level (เช่น `*.module.css`) เพื่อแยกการจัดหน้าของฟอร์มกรอกคะแนนให้เป็นระเบียบ

### 3. การติดตั้งเครื่องมือเพิ่มคุณภาพและความปลอดภัย (Quality & DX Tools)
*   **Zod (Schema Validation):** ติดตั้งไลบรารีเพื่อตรวจสอบความถูกต้องของข้อมูลก่อนส่งเข้าฐานข้อมูล
*   **Drizzle ORM & Postgres client:** ติดตั้งตัวเชื่อมต่อฐานข้อมูลและเครื่องมือสร้างตาราง (Migration)
*   **Vitest (Unit Testing):** ติดตั้งเครื่องมือทดสอบหน่วยประมวลผลสำหรับทดสอบสูตรเกรดถ่วงน้ำหนัก
*   **Playwright (E2E Testing):** ติดตั้งเครื่องมือทดสอบ flow สมัคร, flow เจ้าหน้าที่, การ preview เอกสาร, การปิดรับสมัคร, ranking และ export
*   **Excel Parser/Writer:** ติดตั้งไลบรารีสำหรับอ่าน `.xlsx`, ตรวจ header, preview ผลนำเข้า และ export ranking ตามรูปแบบที่กำหนด

### 4. โมดูลหลักที่ต้องจัดเตรียมตั้งแต่แรก (Core Modules)
*   **Applicant Form Module:** ฟอร์มสมัคร, draft, submitted, rejected correction, validation alert และการปัดเกรดแบบ round half up เป็นทศนิยม 2 ตำแหน่ง
*   **Admin Review Module:** หน้าตรวจเอกสารแบบ split panel, แก้ข้อมูลตาม ปพ.1, อนุมัติ, หรือส่งกลับแก้ไข
*   **Secure File Gateway:** Route Handler สำหรับ stream ไฟล์จาก private directory หลังตรวจสิทธิ์ session/role/application status
*   **Exam Score Import Module:** นำเข้า Excel และจับคู่คะแนนด้วยลำดับรายชื่อตามประกาศ พสวท. เท่านั้น พร้อม preflight validation ก่อนบันทึก
*   **Manual Closing Module:** ปุ่มสำหรับเจ้าหน้าที่กดปิดรับสมัคร ใบสมัคร, lock edit, run ranking และ export Excel ตามลำดับที่ต้องการ

## แผนการทดสอบและความถูกต้อง (Verification Plan)

### การทดสอบแบบอัตโนมัติ (Automated Tests)
1.  **ทดสอบ Unit Test (Vitest):**
    *   สร้างไฟล์ทดสอบสูตรเกรดเฉลี่ยสะสม 5 เทอม เพื่อตรวจสอบว่าฟังก์ชันคำนวณและปัดทศนิยมแบบ "ต่ำกว่า 5 ปัดลง ตั้งแต่ 5 ขึ้นไปปัดขึ้น" ทำงานถูกต้องเสมอ
    *   ทดสอบเลขประจำตัวประชาชน 13 หลัก, รหัสวิชาพื้นฐานที่ตัวเลขหลักที่ 3 ต้องเป็น 1, การจับคู่คะแนนด้วยลำดับรายชื่อ, และ tie-break ranking ด้วยค่าที่ปัดแล้ว
    *   รันคำสั่งทดสอบ: `npm run test` หรือ `npx vitest`

2.  **ทดสอบ E2E (Playwright):**
    *   ทดสอบผู้สมัครกรอกใบสมัครจนถึง submitted
    *   ทดสอบเจ้าหน้าที่ตรวจเอกสารแล้ว approved/rejected
    *   ทดสอบปุ่ม manual หลังปิดรับสมัคร ได้แก่ close, lock edit, run ranking และ export

### การทดสอบโดยผู้ใช้ (Manual Verification)
*   เปิดเซิร์ฟเวอร์พัฒนาระบบชั่วคราว (`npm run dev`) เพื่อให้เจ้าหน้าที่ตรวจสอบความลื่นไหลและดีไซน์ของหน้าเว็บสมัครผ่านเบราว์เซอร์จริง
